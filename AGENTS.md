- Nothing SAP-service-specific is hardcoded in the middleware (service path, entity names, key properties, $expand nav, function paths); the web app derives them from the endpoints in SAP API Settings and sends them per request (x-sap-service-path / -header-entity / -item-entity / -header-keys / -item-keys / -item-nav, or the full path via x-sap-path to /api/odata), with middleware/.env as fallback — so any OData service works without code changes.
- Middleware URL and proxy secret are global (Connection & Credentials tab, stored as reserved '__connection__' row in sap_api_configs) and override per-API values; why: change once, every API follows. SAP user/password stay in middleware/.env, never in the browser.
